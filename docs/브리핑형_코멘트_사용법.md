# 브리핑형 매출실적 코멘트 사용법

## 1. 바뀐 내용

이번 변경은 특정 월의 PDF를 수정한 것이 아니라 코멘트 생성 소스코드 자체를
변경한 것입니다. 수정된 코드를 GitHub 저장소에 반영한 뒤에는 매월 원자료만
교체해도 같은 순서와 문장 구조로 보고서가 생성됩니다.

브리핑 순서는 아래와 같습니다.

1. 전월 대비 부문 전체 매출 증감
2. 전년 동월 누계 대비 당년 누계 비교
3. 주요 품목별 매출·판매량·평균단가 분석
4. 평균단가 급변 품목의 가격효과·제품믹스 효과
5. END USER별 전월 대비 증감액
6. 신규·기존 거래처 판단

## 2. 월별 입력자료

2026년 6월을 예로 들면 다음과 같이 준비합니다.

```text
data\2026-06\input
├─ 20266월누계.xlsx
├─ 20256월누계.xlsx
├─ 기타 기존 보고서 입력파일
└─ customers
   ├─ 1.xlsx
   ├─ 2.xlsx
   └─ 3.xlsx
```

`20266월누계.xlsx`와 `20256월누계.xlsx`는 각각 1~6월 누계 원자료여야
합니다. 자동화는 연도를 기준으로 1월부터 보고월까지만 다시 필터링해 비교합니다.

거래처 파일의 역할은 고객별 증감 근거 확인입니다. 전년 거래 이력까지 자동으로
판단하려면 `1.xlsx`, `2.xlsx`, `3.xlsx`에 최소한 전년도와 당해 연월 데이터가
함께 들어 있어야 합니다.

예를 들어 스텐의 `2.xlsx`에는 아래 기간이 포함되어야 합니다.

```text
2025년 거래내역 + 2026년 1~6월 거래내역
```

## 3. 실행방법

`run_monthly_report.bat`을 더블클릭하고 연도와 월을 입력합니다.

```text
Enter report year: 2026
Enter report month: 6
```

직접 실행하려면 다음 명령을 사용합니다.

```powershell
python monthly_report_final.py --year 2026 --month 6
```

## 4. 결과파일

```text
data\2026-06\output
├─ 코멘트_6월.md
├─ 코멘트_6월.pdf
├─ 코멘트_6월_상세.md
└─ 코멘트_6월_상세.pdf
```

- `코멘트_6월.*`: 팀장 브리핑용 간결한 보고서
- `코멘트_6월_상세.*`: 수치 확인과 예외 검토용 상세 보고서

## 5. 단가 원인탐색 기준

모든 보고서 품목의 매출·판매량·평균단가를 일괄 계산합니다. 이후 평균단가
변동이 기준 이상인 품목만 상세 원인을 문장으로 표시합니다.

계속 판매된 제품의 효과는 다음과 같이 계산합니다.

```text
믹스효과
= (당월 판매비중 - 전월 판매비중)
  × (전월 제품단가 - 전월 전체 평균단가)

가격효과
= 당월 판매비중
  × (당월 제품단가 - 전월 제품단가)
```

신규·중단 제품은 전월 전체 평균단가보다 높은지 낮은지를 기준으로 고단가/저단가
신규·중단 효과로 분류합니다. 각 세부 효과의 합계는 전체 평균단가 변동과
대사됩니다.

기본 기준은 `sales_rules.py`의 `COMMENT_THRESHOLDS`에서 관리합니다.
예를 들어 평균단가 5% 이상부터 상세 원인을 표시하려면 아래 값만 변경합니다.

```python
"unit_price_pct": 5.0,
```

## 6. GitHub에 반영하는 방법

수정파일을 저장소 폴더에 덮어쓴 뒤 저장소 폴더에서 아래 명령을 실행합니다.

```powershell
git status
git diff
python -m unittest discover -s tests -v
git add comment_generator.py monthly_report_final.py sales_rules.py run_monthly_report.bat README.md docs tests
git commit -m "Add briefing comments with volume price mix and YTD comparison"
git push
```

`git diff`에서 원하지 않는 파일이나 원자료가 포함되지 않았는지 반드시 확인합니다.
원자료·거래처파일·완성 보고서는 GitHub에 올리지 않습니다.

## 7. 월별 확인사항

1. 당해·전년 누계 Raw의 보고월이 동일한지 확인
2. 거래처파일에 `출고요청년월`과 END USER가 있는지 확인
3. 브리핑형 PDF의 부문 합계가 완성 엑셀과 일치하는지 확인
4. 단가 원인 합계가 전체 평균단가 변동과 대사되는지 확인
5. 신규 거래처로 표시된 고객은 거래처명 표기 차이가 없는지 확인
